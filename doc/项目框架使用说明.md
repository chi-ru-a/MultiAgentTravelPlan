# planMultiAgent 项目框架使用说明

本文档只说明框架在当前代码中的实际落点，重点解释 FastAPI、LangGraph、LangChain、向量检索和 React 如何串联。

## 1. 技术栈分工

| 技术 | 当前职责 | 主要位置 |
| --- | --- | --- |
| React + TypeScript + Vite | 聊天界面、消息列表、思考链和 SSE 消费 | `frontend/src/` |
| FastAPI | HTTP API、WebSocket、CORS、GZip、生命周期管理 | `backend/app/main.py`、`backend/app/api/` |
| LangGraph | Supervisor、Worker Agent、Send 并行路由、状态聚合、MemorySaver | `backend/app/graph/` |
| LangChain | Tool、ChatOpenAI、消息类型、ReAct Agent 适配 | `backend/app/agents/`、`backend/app/utils/` |
| Qdrant/Elasticsearch | 知识库向量存储和相似度检索 | `backend/app/vectors/` |
| OpenAI 兼容服务 | 对话模型和 Embeddings 模型 | `backend/app/utils/llm_client.py`、`backend/app/vectors/embeddings.py` |

## 2. FastAPI 的使用方式

### 2.1 应用创建和生命周期

应用入口是 `backend/app/main.py`。应用启动时执行 lifespan：

1. 输出启动日志；
2. 调用 `warmup_workflow()` 预热工作流；
3. 应用关闭时输出关闭日志。

FastAPI 注册 `/api/v1` 路由和 `/ws` WebSocket。当前版本兼容代码使用 `add_api_websocket_route`。

### 2.2 路由和接口

当前聊天路由位于 `backend/app/api/routes.py`：

| 接口 | 作用 |
| --- | --- |
| `GET /api/v1/test` | 测试路由 |
| `GET /api/v1/health` | 健康检查 |
| `POST /api/v1/chat/stream` | SSE 流式聊天 |
| `GET /docs` | OpenAPI 文档 |
| `WS /ws` | WebSocket 聊天接口 |

请求体由 `ChatRequest` 校验，核心字段包括消息内容、会话 ID 和是否展示思考过程。

### 2.3 流式响应

`POST /api/v1/chat/stream` 使用 `StreamingResponse` 返回 `text/event-stream`。工作流使用 `stream_mode="custom"`，统一转发：

- `thinking_stream`：Supervisor 和 Worker 的进度；
- `content_stream`：模型回答内容；
- `session_id`、`thinking_start`、`thinking_end`；
- `response_end` 或 `error`。

前端在 `frontend/src/api/chat.ts` 和 `frontend/src/store/chatStore.ts` 中消费这些事件。

## 3. LangChain 的使用方式

### 3.1 对话模型

`backend/app/graph/agents.py` 使用 `ChatOpenAI`，但通过 `LLM_API_BASE` 连接任意 OpenAI 兼容服务：

```python
ChatOpenAI(
    model=settings.LLM_MODEL,
    api_key=settings.LLM_API_KEY,
    base_url=settings.LLM_API_BASE,
    temperature=settings.LLM_TEMPERATURE,
)
```

因此项目并不要求一定使用 OpenAI，当前 `.env` 使用的是 DashScope 兼容接口。

### 3.2 Tool 和 ReAct Agent

`backend/app/agents/tools/` 定义具体能力：

- `TicketSearchTool`
- `WeatherSearchTool`
- `KnowledgeBaseTool`
- `ChitchatTool`

`backend/app/graph/agents.py` 再通过 `create_react_agent` 为每个工具创建一个带模型、提示词和工具绑定的 Worker Agent：

```python
agent = create_react_agent(
    model=llm,
    tools=[tool_instance],
    name=tool_name,
    prompt=prompt,
)
```

因此 Tool 不是 Agent 本身；Tool 是能力函数，Agent 是可以理解任务并决定调用 Tool 的 LLM 执行单元。

## 4. LangGraph 的实际使用方式

与只间接使用 LangGraph 的项目不同，本项目直接使用了 `StateGraph` 和 `Send`：

- `backend/app/graph/state.py`：定义 `AgentState`；
- `backend/app/graph/langgraph_workflow.py`：创建图、注册节点和路由；
- `backend/app/agents/nodes/supervisor.py`：意图识别和任务拆分；
- `backend/app/agents/nodes/synthesizer.py`：多结果汇总。

主图逻辑可以概括为：

```text
START
  -> supervisor
  -> 单任务 Worker 或 Send 并行分发多个 Worker
  -> synthesizer
  -> END
```

每个 Worker 实际上是一个 `create_react_agent` 编译出的子图，主图负责调度这些子图。

## 5. Qdrant 和 RAG 的代码落点

`KnowledgeBaseService` 根据 `VECTOR_DB_TYPE` 选择 Qdrant 或 Elasticsearch。Qdrant 访问器负责：

1. 接收文本向量；
2. 调用 Qdrant collection 的搜索接口；
3. 返回内容、标题、来源和分数。

`VectorEmbeddingsAccesserProxy` 负责在写入和查询前调用 Embeddings 服务，把文本转换为稠密/稀疏向量。

当前仓库没有内置文档、导入命令或知识库管理路由。`add_document()` 和 `add_documents()` 是服务层方法，必须由其他代码主动调用。

## 6. 前端的使用方式

前端使用 React + Zustand：

- `App.tsx` 组织聊天页面；
- `ChatInterface.tsx` 组织输入、消息和思考链；
- `chat.ts` 发起流式请求；
- `chatStore.ts` 保存会话、消息、思考事件和流式文本；
- Vite 开发服务器默认端口为 5173，若被占用会自动尝试其他端口。
